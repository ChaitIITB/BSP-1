W₀·xfrozen path, d = 1536
  • W₀ (d × k) is never updated. It maps an input of size k to an output of size d. The bypass learns the change ΔW = (α/r)·B·A.
  • Rank bottleneck: the signal is squeezed through r = 8 numbers, so ΔW has rank at most 8, however large the layer is.
  • Start: A is random (Kaiming-uniform), B is all zeros, so ΔW = 0 and the model begins exactly as the base model.
  • Training: only A and B receive gradients and optimizer state. W₀ stays in fp16 and needs neither.
  • Dropout is applied to the input of the bypass only, not to W₀·x.
  • After training: merge W = W₀ + (α/r)·B·A for inference with no extra cost, or ship just A and B (about 4 MB here).

What d, k, r and α are, and how the "division by r" works

SymbolWhat it isWho sets itOur value
d, kOutput and input size of the layer being adapted: W₀ is d × kThe model architecture (fixed)q_proj 1536 × 1536; v_proj 256 × 1536
rRank: the inner dimension of the factorisation (rows of A, columns of B)You, as a hyperparameter8
αScaling constantYou, as a hyperparameter16
A, BThe trained matrices: A is r × k, B is d × rLearned by gradient descentrandom / zeros at start
  • "Division by r" is a scalar, not a matrix operation. The product B·A is multiplied by the constant α/r = 2. In peft this is scaling = lora_alpha / r, applied to the bypass output.
  • Why divide by r: a bigger r adds more terms to B·A and would grow the update. Dividing keeps its size roughly stable, so the learning rate chosen for one r still works for another when α is held fixed.
  • Parameter count: A has r·k entries and B has d·r entries, so r·(d + k) in total, against d·k for training the whole matrix.

LoRA · choosing r, α and the target layers

These are hyperparameters, not learned

  • r (capacity). Typical range 4 to 64. A larger r lets the update express more directions (more capacity, more memory, more risk of overfitting on small data). Small r works when the task is a narrow change of behaviour, as the LoRA paper reports.
  • α (strength of the update). Common conventions are α = r or α = 2r. With r = 8 and α = 16 the update is scaled by 2. Raising α is similar to raising the learning rate for the bypass.
  • Which layers. Attention projections are the usual choice. Our setup, inherited from GenRec's code (itself from alpaca-lora), adapts only q_proj and v_proj. Adapting all linear layers often gives a better fit at a higher parameter count.
  • Dropout 0.05 regularises the bypass.
  • In practice they are chosen by convention and a small search: try a few values of r (and α = r or 2r) on a validation set and keep the best.

What we did: no search. We copied GenRec's settings (r = 8, α = 16, dropout 0.05, q and v) and ran once. The validation split was not used. So we cannot say r = 8 is right for this task; a larger r or more target layers is a cheap thing to test, because the trainable count stays around 1–10M.

Fine-tuning script · kaggle_genrec_rank.py

What the script does, in order

1
Data. Loads train/val/test.jsonl. Each record: instruction, input, output, plus the candidate list and the gold order. The validation split is not used in this run.
2
Prompt. instruction, ### Input:, input, ### Response:, then the answer and EOS. Labels are −100 on the prompt, so loss is on the answer only. Truncated at 512 tokens.
3
Model. Qwen2.5-1.5B in fp16, one GPU, gradient checkpointing, then get_peft_model with r = 8, α = 16, dropout 0.05 on q_proj and v_proj.
4
Training. HF Trainer: micro-batch 8 × 4 accumulation = 32, AdamW, lr 3e-4, 10 warm-up steps, cosine decay, fp16 mixed precision, 3 epochs (about 470 steps). Checkpoint every 20 steps, resumable.
5
Test. Greedy decoding, up to 96 new tokens, split on " > ". Valid only if it lists exactly the six given names; invalid answers are completed in input order for scoring, so partial answers get partial credit.
6
Outputs. Paper-count baseline on all test lists, zero-shot on the first 100, then the adapter, results.json and 100 sample predictions.

Measured: 54 minutes on one T4, about 1,413 tokens per second, about 5M training tokens.
